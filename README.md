# James Thiongo — Portfolio

A responsive, static portfolio site that can be hosted with GitHub Pages. It uses plain HTML, CSS, and JavaScript; no build step or package installation is required.

## Personalize before publishing

1. Personalize the tagline and location in `index.html`, `resume.html`, `projects.html`, and `labs.html`.
2. Replace `assets/profile-placeholder.svg` with a professional portrait and update the image path and alt text in `index.html`.
3. Fill in the resume with accurate education, experience, certifications, and skills.
4. Replace the three project templates with real projects and working repository links.
5. Replace the lab templates with challenges you completed in authorized environments. Add permitted, sanitized screenshots and your own lessons learned.
6. Update the email, LinkedIn, GitHub, and any other contact details in `index.html` and `resume.html`.
7. Search the site for remaining examples such as `YOUR-USERNAME`, `Add`, and `goes here` before publishing.

## Publish with GitHub Pages

1. Create a GitHub repository. For a user site, name it `YOUR-USERNAME.github.io`; for a project site, use any repository name.
2. Add the files in this folder to the repository and push them to GitHub.
3. In the repository, open **Settings → Pages**.
4. Under **Build and deployment**, choose **Deploy from a branch**, select your publishing branch (usually `main`) and the root folder (`/`), then save.
5. Wait for the Pages deployment to finish. The site URL is `https://YOUR-USERNAME.github.io/` for a user site or `https://YOUR-USERNAME.github.io/YOUR-REPOSITORY/` for a project site.
6. Open the published URL and test every page, navigation link, external profile link, and contact link.

## Grading submission

Open `grading-submission.html` in a browser after publishing. Replace the example URL, capture genuine screenshots of the live Home, Resume, Projects, Lab Challenges, and Contact sections, then insert them into the sheet (or print the page to PDF after adding the images). Do not submit the screenshot placeholders as evidence.

All lab content should stay within the rules of the training platform and should not expose credentials, personal information, or restricted challenge solutions.
